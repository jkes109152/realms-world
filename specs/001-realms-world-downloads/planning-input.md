## 第一個實作里程碑：驗證 Sites 與 Realms 相容性

正式技術計畫與任務必須先安排下列驗證，再排完整產品實作：

1. Microsoft 裝置碼／官方授權流程能在 Sites 正式執行環境完成；等待授權採分次查詢，
   不依賴永久常駐的登入程序或本機檔案快取。
2. 已保存的授權能在跨請求及新工作階段中使用，並完成一次真實續期；
   續期競爭、撤回、取消、逾時與解除連線的結果明確。
3. 正確辨識帳號、Realm 擁有者及世界欄位。驗證官方歷史存檔是否可按欄位查詢或可靠對應；
   不得直接假設套件接受 `slotId` 就表示回傳列表已按欄位隔離。
4. 最新及指定歷史存檔都能取得可下載檔案；下載附帶的授權不能回傳給公開瀏覽器。
5. 以串流把來源檔案轉送給瀏覽器原生下載，不使用整檔 Buffer、Blob 或落盤暫存來假裝串流。
   測試至少 3 個並行的 1 GiB 模擬檔，並驗證真實最大世界下載與一份實際遊戲匯入。
6. 對下載來源、重新導向、準備中回應、上游限流及失效來源，訂定不會洩露授權、
   不形成任意網址代理、不無限重試的策略。
7. 若必要能力無法在 Sites 達成，記錄可重現證據與需調整的方案並回報，
   不自行改成外部主機、不取消歷史下載、不把模擬串接當成已完成。

目前只有文件與原始碼調查；上述項目皆尚未完成真實驗證。

## 技術計畫必須補齊的設計

- 授權串接：使用可適配 Workers 的 HTTP 與加密能力；評估 PrismarineJS 套件中可重用部分，
  不預設 Node.js 檔案快取、整檔下載或長時間輪詢可直接部署。
- 帳號維護：管理員初始建立、密碼雜湊、修改／重設密碼、工作階段失效與防止重放。
  不把實際帳號密碼寫入規格、環境範例或 Git。
- 資料與邊界：將公開世界、官方欄位／存檔、管理員及加密連線的關聯寫入資料模型；
  所有公開查詢與下載皆重新檢查發布狀態與歸屬。
- 介面契約：公開世界列表、存檔列表與下載；後台登入、連線、發布設定與紀錄。
  定義可理解的錯誤、下載準備狀態與來源失效處理。
- 執行限制：依已驗證的 Sites 限制決定登入／下載頻率門檻、傳輸並行限制、上游重試上限、
  授權續期協調及短期資料有效期，不宣稱下載流量免費或不限量。
- 資料生命週期：紀錄保留 30 天；在只有請求驅動、無排程的第一版中，
  定義過期資料不可讀取及清理策略，不為清理工作擅自新增定時服務。
- 測試：登入與越權、發布隔離、跨欄位下載、解除連線、限流、來源消失、傳輸中斷與紀錄語意。
  區分可自動化的測試、需要真實帳號的驗收，以及需要使用者在遊戲確認的匯入結果。

## 後續執行與發布

- 既有 `.specify/`、`.agents/` 與本機 Spec Kit 工具必須保留；Sites starter 需要空目錄時，
  先在獨立暫存目錄準備，再合併必要的新檔案，不覆蓋現有 SDD 內容或初始化另一個產品。
- GitHub 保存主要原始碼；Sites 需要自己的來源遠端時使用獨立遠端，保留 GitHub `origin`，
  發布內容與打包來源對應同一個完整提交。
- Site 初始資料不自動發布任何世界；管理員完成真實授權及明確選擇公開欄位後才開放其下載。
- 實作驗收通過後，依 Sites 回傳的確切驗證、路由與憑證狀態，在 Bluehost 設定網域。
  不猜測 CNAME／A 記錄，不把等待 DNS 或登入的工作標為已完成。
