# Realms World 專案憲章

## 核心原則

### I. 規格驅動與需求可追溯

功能開發必須以功能規格、技術計畫與任務清單為依據，依序描述使用者需要什麼、
如何實作及如何驗收。影響使用者的能力必須對應可驗收的需求與情境。
文件必須區分已確認需求、合理預設與待實測的相容性，不得把尚未驗證的串接當成可用功能。
變更範圍時必須同步更新受影響的規格與驗收條件。

### II. 擁有者授權與公開範圍隔離

網站必須僅使用管理員已授權的 Realms 擁有者帳號；網站管理員身分不得被當作額外遊戲權限。
每個世界欄位必須預設不公開，只有管理員明確開放後才能讓匿名訪客查看與下載。
公開範圍必須包含該欄位的最新及官方仍可取得的歷史存檔，不得混入其他欄位或未公開世界。
每次管理操作及新下載請求必須在後端檢查對應權限與發布狀態，不能只依賴畫面隱藏控制項。

### III. 憑證保護與可解除的連線

網站必須使用管理員自訂的網站帳號密碼；Microsoft 授權必須在其提供的授權頁面完成。
網站不得索取 Microsoft 密碼。網站密碼必須以適合密碼儲存的不可逆雜湊保存；
需要重用的 Microsoft 授權資料必須在後端加密保存，且加密金鑰與資料分開管理。
原始密碼、授權權杖與其他秘密不得進入公開頁面、公開回應、一般日誌或 Git 歷史。
解除連線必須刪除網站持有的該連線授權資料並拒絕新的下載；重新授權不得自動重新發布世界。

### IV. 依官方來源提供下載、如實呈現結果

第一版必須以手動下載為核心，世界檔案只能在傳輸期間經過網站，不能形成可再次下載的持久副本。
大型世界必須使用串流傳輸，禁止先把完整檔案放入應用程式或瀏覽器記憶體後才提供下載。
「最新」必須指官方當時提供的最新可下載存檔，不得宣稱是未儲存的遊戲即時狀態。
官方移除存檔、權限失效或服務中斷時必須明確呈現不可用狀態。
請求下載、伺服器傳輸結束與已確認的傳輸失敗必須分別記錄；
無法確認結果時必須保留未知狀態，不得宣稱使用者已儲存檔案或成功匯入遊戲。

### V. 實際環境驗證與可重現發布

正式上線前必須在 Sites 執行環境驗證 Microsoft 授權、續期、Realm 擁有者識別、
世界欄位與存檔對應，以及實際世界檔下載。
權限隔離、授權生命週期、下載失敗與大型檔案傳輸必須有對應測試；
模擬資料不得取代真實 Realms 串接及至少一次基岩版匯入驗證。
發布內容必須可追溯到已保存的 Git 提交，檢查結果必須區分通過、失敗與尚未執行。
遇到 Sites 的必要能力限制時必須記錄實測證據並回報，不得自行增加外部主機或刪除核心需求。

### VI. 所有 SDD 文件使用繁體中文

本專案所有 SDD 文件必須以繁體中文撰寫，適用於新建文件與既有文件。
範圍包含憲章、功能規格、澄清紀錄、研究、技術計畫、資料模型、
介面契約的人類可讀說明、快速開始指南、任務清單、品質檢查表、分析、收斂與交接文件。

標題、段落、表格、檢查項目、驗收情境、備註與自行撰寫的說明註解都必須使用繁體中文；
不得直接沿用英文模板敘述或以簡體中文交付。採用模板時必須保留必要結構，
並將供人閱讀的內容改寫為繁體中文。

產品與套件專有名稱、檔名、路徑、指令、網址、程式碼、資料欄位、
需求編號與工具要求的固定識別字可保留原文，以維持正確性與工具相容性；
其周圍的解釋仍必須使用繁體中文。不得以整份文件屬於技術文件為由豁免。

文件審查必須檢查上述語言要求；既有不符內容必須補正，
不得因過去已完成審查而宣稱仍符合本憲章。此原則讓需求討論、實作交接與驗收使用一致語言。

## 專案約束

- 第一版為單一最高管理員與匿名下載訪客；最高權限指管理本網站及其已授權的 Realms 下載範圍。
- 網站必須部署於 Sites，正式網域為 `realms.jkesbyebye.com`，DNS 由 Bluehost 管理。
- Git 必須根植於此專案資料夾，主要遠端為 `https://github.com/jkes109152/realms-world`；
  功能分支使用 `codex/` 前綴，不能提交或修改其他上層專案。
- 網站必須提供繁體中文介面，支援手機與電腦，時間以台灣時區顯示。
- 第一版不包含公開註冊、多管理員、世界檔案持久儲存、定時備份、上傳替換、還原、
  Realm 開關或成員管理；新增這些能力前必須更新功能規格。
- 管理員初始建立及忘記密碼重設必須走受保護的維護流程，不提供匿名的管理員註冊入口。
- Sites 登入不得取代已選定的自製管理員帳號系統；匿名下載入口不得要求 ChatGPT 登入。

## 開發流程與品質門檻

1. 完成憲章與功能規格；有會改變範圍的疑義時先澄清，再進入技術規劃。
2. 技術計畫必須記錄選型、外部依賴、資料生命週期及權限邊界，並完成憲章符合性檢查。
3. 任務清單必須將 Sites／Realms 可行性驗證排在完整產品實作之前，且包含規格要求的驗收工作。
4. 實作前必須檢查規格、計畫與任務一致性；實作後必須檢查未完成項目並保留證據。
5. 匿名存取、管理員權限、真實下載、錯誤處理與秘密不外洩均經驗證後，才能開放正式下載。
6. 下游流程讀取本憲章；不得為了繞過品質門檻而改寫模板或將未完成項目標示完成。
7. 所有 SDD 文件的產出與審查必須檢查繁體中文要求；語言不符時先補正，再宣告文件符合憲章。
